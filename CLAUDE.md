# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Orb is a 2D Newtonian N-body solar system simulation written in Rust with [Bevy](https://bevyengine.org/) 0.15. It runs natively or as a WebAssembly build deployed to GitHub Pages. The point it demonstrates: gravity is frame-independent, so any body (or arbitrary point) can be treated as the center — focusing on the Sun gives the heliocentric model, focusing on Earth recovers the Ptolemaic geocentric model with its epicycles.

## Commands

Requires `python3` and `cargo`. All workflows go through the `makefile`.

- `make init` — **run this first.** Runs `index.py` to generate `data/planets.json`. The native/wasm build will not compile without it (see Data pipeline below).
- `make run` — `cargo fmt` then `cargo run --release` (native window).
- `make build` — release wasm32 build + `wasm-bindgen` + post-processing into `./build/` (see Web build below).
- `make prep` / `make deploy` — assemble `dist/` from `index.html` + `./build`. **Both require `make build` to have run first** (they `mv ./build` and do not declare it as a make dependency). `deploy` additionally publishes via `npx gh-pages`.

There are no tests and no separate lint step; `cargo fmt` runs as part of `run`/`build`.

## Data pipeline

`data/planets.json` is **embedded into the binary at compile time** via `include_str!("../data/planets.json")` in `src/planets.rs`. It is gitignored-adjacent (committed, but regenerated by `index.py`). Consequences:

- Editing planet initial conditions means editing/regenerating the JSON, then rebuilding — there is no runtime data loading.
- `index.py` downloads JPL's `de440.bsp` ephemeris (~cached in `data/`, gitignored) and computes heliocentric ecliptic position/velocity for each planet at `EPOCH_JD = 2460000.5` (~2023-02-25).
- Values are **scaled, not physical**: every position/velocity is multiplied by `vel_scale` so the largest position component equals 10. The Rust side reads these scaled units directly. Velocities are additionally multiplied by `DAYS_PER_YEAR` (365.2422) at spawn time in `spawn_solar_system`.

## Simulation architecture (`src/main.rs`, `src/planets.rs`)

Standard Bevy ECS app. Two files:

- **`planets.rs`** — defines the `CelestialBody` and `Velocity` components and `spawn_solar_system`, which spawns the Sun plus 8 planets. Masses are expressed relative to Earth mass (`M_E = 3.003e-6` solar masses) and the Sun (`SOL = 1.0`); these are passed straight into the gravity calc, so the mass *units* and `G_CONST = 1.0` together define the (non-SI) simulation scale.
- **`main.rs`** — the app. The `Update` schedule is a single `.chain()`ed sequence and **order matters**: `gravity_physics` → `update` → `inputs` → `follow` → `trail` → `make_hud` → `make_controls`.
  - `gravity_physics`: full O(n²) pairwise Newtonian acceleration (`a = G·m₂/r²`), integrated semi-implicit Euler with `dt = TIME_STEP * sim_speed`. Accelerations are collected into a `Vec` first, then applied — do not fold the position update into this loop or you break the all-pairs symmetry.
  - `update`: integrates position from velocity.
  - `inputs`: mouse wheel / arrow keys for zoom and sim speed; right-drag pans; left-click picks the focused body (hit-test against `body.radius`). The focused body becomes the camera center — this is the "any body as center" mechanic.
  - `follow`: drives the `Camera2d` from `SimulationState` (zoom → scale, focus target → translation).
  - `trail` draws bodies as gizmo circles; `make_hud`/`make_controls` update on-screen text only when `SimulationState` changes.

`SimulationState` (a `Resource`) holds all interactive state: `focus_target`, `camera_zoom`, `camera_offset`, `sim_speed`.

## Web build specifics

`make build` does two non-obvious post-processing steps after `wasm-bindgen`:

1. Copies `src/orb.svg` into `build/` (used as favicon and loader graphic).
2. `sed` replaces `fetch(module_or_path)` with `patch(module_or_path)` in the generated `build/orb.js`. `patch` is a custom loader defined in `index.html` that streams the wasm download and drives the orbital progress animation. **This rename is brittle** — if a `wasm-bindgen` upgrade changes the generated loader's `fetch(...)` call site, the `sed` silently no-ops and the progress UI breaks.

`index.html` calls `init()` and swallows the benign `"This isn't actually an error!"` thrown by wasm-server-runner's control-flow, removing the loading overlay on success.

WASM targets need the `getrandom` js-backend config in `Cargo.toml` (`getrandom_backend="wasm_js"` rustflag + both getrandom 0.2/0.3 with js features); this is required for Bevy to link on `wasm32-unknown-unknown`.
