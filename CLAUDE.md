# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Orb is a 2D Newtonian N-body solar-system simulation written in TypeScript, rendered to an `OffscreenCanvas` from a Web Worker and built with Vite. It runs in the browser and deploys to GitHub Pages. The point it demonstrates: **the solar system has no center** — click any body to make it the origin `(0,0)` and the physics is unchanged. Focusing the Sun gives the heliocentric model (clean ellipses); focusing the Earth recovers the Ptolemaic geocentric model (epicycles).

> Earlier versions were written in Rust + Bevy (compiled to wasm). That is gone; the project is now plain TypeScript. Ignore any Rust/Bevy/cargo references you find in old commits.

## Commands

Needs `node`. `python3` is only needed to regenerate the planet data.

- `npm install` — first.
- `make dev` (`npm run dev`) — Vite dev server with hot reload.
- `make build` (`npm run build`) — production build into `./dist`.
- `make deploy` (`npm run deploy`) — build + publish `./dist` to GitHub Pages via `gh-pages`.
- `make init` (`npm run init`) — regenerate `data/planets.json` from JPL's DE440 ephemeris (`index.py`).
- `npm run typecheck` — `tsc --noEmit` (the build itself uses esbuild and does not type-check).
- `eastwood src/` — lint. Rules are pinned in `eastwood.toml`; CI-clean means zero output.

## Architecture

**Threading (the core design).** `src/main.ts` runs on the main thread and does nothing but bootstrap the worker and forward input — it `transferControlToOffscreen()`s the canvas and posts pointer/wheel/key messages. `src/worker.ts` owns the `OffscreenCanvas` and runs **both physics and rendering in a single `requestAnimationFrame` loop**, so the UI thread never blocks. It is deliberately *one* worker, not two: splitting physics and rendering across workers would require `SharedArrayBuffer`, which needs COOP/COEP cross-origin-isolation headers that GitHub Pages cannot set. The main↔worker message protocol is the `ToWorker`/`FromWorker` unions in `src/types.ts`.

**Physics (`src/sim/`, renderer-agnostic, pure).**
- `physics.ts` — O(n²) Newtonian acceleration (`G = 1`, masses in solar masses) integrated with **velocity-Verlet**. `step` takes `aCur`/`aNext` scratch arrays: `aCur` must hold the acceleration at the current positions on entry and is updated in place on exit, so the loop does one force eval per step. Units are **pre-scaled, not SI**.
- `bodies.ts` — `DEFS` (the body table; index order is the body id, `0 = Sun`) and `createSim`, which reads the embedded `data/planets.json`.
- The worker caps per-substep `dt` at `TIME_STEP * 1.5` and sub-steps at high `speed`, so the 0–200× speed slider stays numerically stable (verified: energy drift ~0.03% at the cap; blow-up only past `dt≈0.05`).

**Data.** `data/planets.json` is generated by `index.py` from JPL DE440 and **pre-scaled so the system fits a ~[-10, 10] box**. It is `import`ed directly (bundled into the worker chunk) — there is no runtime fetch. Editing initial conditions means regenerating it with `make init`.

**Rendering (`src/render/renderer.ts`).** Bodies plus trails. Trails are a ring buffer of **world** positions, drawn in the current reference frame as `body(t) - reference(t)` — that projection is what turns ellipses into epicycles. A frame switch is animated: the reference is `lerp(fromRef, toRef, blend)` eased over `TRANSITION_MS`, so the whole scene and its trails morph between frames with **no snap**. Trails fade to transparent over the most recent `FADE_SAMPLES`, and recording is gated on the sim advancing so a paused trail doesn't decay away.

**Deploy.** `vite.config.ts` sets `base: './'` so relative asset URLs work under the GitHub Pages project path (`plutoniumm.github.io/orb/`). The worker is referenced via `new URL('./worker.ts', import.meta.url)`.

## Conventions

- **Lint/format is enforced by eastwood** (`eastwood.toml`): object literals with 3+ keys are one-key-per-line, blank lines around blocks/returns, braces on `if/else` branches. Run `eastwood src/` and keep it clean.
- **Hot paths are allocation-free**: classical `for` loops only (no `.map`/`.filter`/`.forEach`/spread in `src/`), reuse typed arrays and scratch fields (e.g. `Renderer.computeRef` writes `refX`/`refY` instead of returning a tuple; trail alpha uses `ctx.globalAlpha` rather than building `rgba()` strings).
- **Comments** are kept to disambiguation only — units, non-obvious contracts/sentinels, and the reference-frame concept.
- Requires a browser with `OffscreenCanvas` 2D in workers (Chrome/Edge, Firefox, Safari 16.4+).
